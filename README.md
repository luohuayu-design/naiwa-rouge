# 蛙步 · 夜行（naiwa-rouge）

一个用 Three.js 做的**幸存者类肉鸽游戏**原型。角色是「奶蛙」，来自同作者的音游《蛙步》。纯静态站点（无构建、无 CDN、零依赖，Three.js r160 本地内置），GitHub Pages 发布，手机浏览器兼容是硬约束（不用 importmap / 顶层 await）。

## 玩法

- **场景 / 移动**：深夜草地圆形竞技场，可走半径随关卡 15~20（撞边沿切向滑走）。左半屏按住拖动出浮动摇杆；WASD / 方向键也可用。右侧预留技能键。
- **开始 / 选关**：加载完进标题页 → 选「开始游戏」先选关卡（通关上一关才解锁）→ 选难度 / 诅咒 → 问是否教程 → 开打。第一关 20 回合共 273 只，怪随回合变强（R20 生命 ×4.04 / 伤 ×2.90 / 速 ×1.86 / **出手间隔 ×0.69**），清完通关、生命归零倒下。
- **存档**：每回合自动落档；局内「存档退出」回主菜单；主菜单「读取存档」列中途退出的局（按退出时间排序）；彻底打完自动清档。调试局（`?debug=1`）默认不落档，要落加 `&keepsave=1`。
- **存档备份（第 78 块 → 第 97 块三件套 → 第 99 块简化 → 第 104 块定型）**：设置里一排键 —— **导出文件**（`.json` 落盘）、**复制存档码**、**导入文件**、**粘贴存档码**、以及一行**本机自动备份**（3 份）。「分享文件」第 97 块加过、第 104 块**按用户要求删掉**（和导出文件效果一样，多一颗键反而要多想）。
  - **导出文件**（第 104 块重写）：两点改动都是为了「点了真能下下来」—— **文件名纯 ASCII**（`wabu-save-20261027-2216.json`，中文名只进 toast），**微信 / QQ / X5 / `; wv)` 内核改走 `data:` URL**（`blob:` 被移交给 QQ 浏览器后是死链，这正是「跳过去了但不下载」的原因）；不会被移交的内核仍走 `blob:`（大存档不吃 URL 长度）。点完还会出现一条**「没看到下载？点这里手动保存」**的兜底链接，长按就能另存。

- **帧率自适应**：战斗中连续 2 秒低于 40 帧就自动往下压一档（像素比 → 关阴影 → 更低像素比），稳在 52 帧以上 5 秒再逐级升回你选的那档；全程不写存档，设置里那个值始终是你选的。

## 运行

**加载是按需的（第 72 块 + 第 80 块）**：首屏只拉主角 + 第一关要用的 4 只怪（约 3MB，原来 17 只全拉约 8.7MB）；选了别的关，在「点开始、标题页淡出」那一刻按差集补那一关缺的模型，加载页复用同一层遮罩显示进度。已经加载过的怪不会重复下载，重进同一关零请求。第 80 块又加了三层：

- **并发下载**：原来是 `for + await` 串行，第六关 11 只怪（约 5MB）一只一只排队；现在 4 路并发，同样的量大约 1/3 时间。某一只失败也不再连坐（以前一 reject 整关都进不去）。
- **进关后静默预载下一关**：开局 4 秒后（第一波已经稳住）悄悄把下一关缺的模型拉下来，并发压到 2，不跟战斗抢主线程。真正进关时差集是空的 —— 零等待。
- **进度写清「3/5」**：光有一条不会动的进度条，等超过三秒就会被当成卡死；现在标题里写着「正在进入第六关 · 3/5」。

**进站加载 + Service Worker 本地缓存（第 79 块）**：首屏要拉 **52 个文件 / 约 1MB**（`three.module.js` 一个就 1.2MB 未压缩，38 个 ES module 全部独立请求，这是「无构建 + 零 CDN」的代价，绕不开）。而 GitHub Pages 只给 `Cache-Control: max-age=600` —— 隔十分钟再进就等于重新下一遍，国内直连 6 秒起步。

- 新增根目录 **`sw.js`**：带 `?v=N` 的 js/css 走**缓存优先**（发版铁律是全部一起 bump，所以同一个带版本号的 URL 内容永远不变，永久缓存绝对安全），其它静态资源（glb / webp / 字体 / 音频）走**先给缓存、后台更新**；`index.html` 一律放行，保证发版能立刻拿到新版。同一个版本号内二次进站基本**秒开**。
- 顺带**自动重试**：网络抖动时同一个请求最多试 3 次（退避 250 / 500ms）。以前任何一个依赖请求被掐断，整个模块图就废、游戏直接打不开 —— 这是「偶发白屏」的根源。
- 只缓存**完整成功（200）**的响应；404 原样交回去不重试（重试只是让页面多等 750ms 再拿到一个网络错误）。
- 不支持 SW 的老浏览器（iOS 11.3 以前 / 老 WebView）静默跳过，行为跟以前完全一样。
- **`?nosw=1`** 是后门：完全不经过缓存，也不往里写。SW 万一哪天出问题，玩家 / 我都可以用它绕过。

**加载页的提示也重写了（第 79 块）**：以前是「9 秒没起来就报**加载超时**」—— 那是**误报**，它只代表「9 秒内没跑完」，不代表失败，而且红色小字的颜色字号写死在元素上、后面加载成功了也不还原。现在：

- **9 秒** → 只多一行黄字「网络有点慢，还在加载……」，百分比和进度条照常走，不染红、不判死；
- **25 秒** → 再给一个「重新加载」按钮，但仍然不写死；
- **脚本真的 404 / 解析失败** → 才报红字「脚本加载失败，请检查网络后重试」+ 重试按钮；
- 模块一跑起来（`window.__naiwaBooted`）→ 所有提示自动收掉，文字样式也还原。

**glb 也带版本号了（第 80 块）**：SW 的第 79 块策略只给带 `?v=N` 的 js/css 走「缓存优先」，glb 因为没有版本号只能走「先给缓存 + 后台重下一遍」—— 而怪物模型一共 7MB，**每次刷新、每次重新进关都在后台重下一遍**，玩家进关时带宽被自己抢光。现在新增 `js/assetUrl.js`：`ASSET_V` 从模块自己的 `import.meta.url` 里读（不写死，发版一起 bump），`withV(path)` 给 glb 拼上 `?v=N`。同一版本第二次进站，模型一个字节都不下；换版本 URL 变了，天然拿新模型（第 77 块「换了模型看着像没换」的坑一起堵掉）。

**第六关的并联体重做（第 80 块）**：用户三条反馈 ——「介绍不清晰」「不用成对出现，两个以上就行」「感觉并联体和节点是两个实体，节点在稳定移动、并联体乱转」。查下来最后一条是个真 bug：

- **模型原点离几何体 6 格**。Kenney 的 `machine_generator` 顶点中心在 x≈2 / z≈1.5 格（乘上 3.25 倍缩放就是 6 格多），而电弧、碰撞、血条全按 `e.pos` 算 —— 铁疙瘩飘在六格外、玩家砍的是空气。现在加载时量一次静态网格的包围盒，用一层 `pivot` 把偏移吃进去（**不能直接改 `model.position`**：Three 是 T×R×S，先偏移再旋转，模型会绕着那个偏移点转，摆动 0.16 弧度能甩出 ±1 格 —— 这才是「乱转」的观感）。
- **取消整圈自转**：原来 `model.rotation.y = t × 0.8`，和 root 朝玩家转叠在一起，看着像两个东西。现在只留 ±0.16 弧度的左右机械摆动。
- **两两最小间距 3.0 格**：每帧对每一对做「同性相斥」，靠太近就互相推开（迭代两轮，推完夹回场地）。手机上以前会全挤在主角身边堆成一坨，电弧被压成零长度，禁区成了一个点。
- **电弧重画**：一条线 = 一个 `InstancedMesh`（4 段椭球 + 2 个流光球，1 个 draw call）。折线随相位扭动、光点沿线跑、咬到人时整条爆闪。抬高到模型顶部（原来在半腰，从俯视角被 1.3 格高的铁疙瘩挡住一截），端点从模型边缘起步 —— 线看起来是从铁疙瘩身上长出来的。
- **不必成对**：任意 n ≥ 2 就成网（2 只 1 条、3 只 3 条、4 只 6 条）。第六关第 9 回合特意给了 3 只（奇数）来证明这一点。
- **文案写清机制**：图鉴与「新怪物」卡共用同一份描述 —— n 只连几条、碰到掉 1 点、同一下隔 0.7 秒（站交叉口不会瞬间连扣）、它们之间保持 3 格以上所以中间有活路、拆掉一只它牵的线整片断。顺带给新怪卡的图片加了 `onerror` 兜底：图没了就藏起来，不给玩家看碎图图标（第 75 块就是漏了 `arc.webp`，卡上是个破图）。

**第八关「骨塔寄存层」+ 两只新怪（第 81 块）**：用户选的两套机制 ——「列队推进」和「寄存柜」——不是各玩各的，是串成一个闭环的：**无名者倒下 → 木牌被寄存柜收走 → 柜满 8 块开门 → 把这一沓牌子放回场上，走出来一支新队伍**。正好接上主线 s08「寄存处的骷髅，在等一个永远不会来的队伍」。

- **无名者**（`ranker`，全场唯一不追人的怪）：骨架队列沿**固定方向平移**（`speed 1.05` 是队列平移速度，不是追击速度），朝向 = 队伍方向而不是玩家方向 —— 你跑到它背后它也不回头。**撞到场边才会换向**（朝场地中心 ±20° 扰动，不是纯反向）。队形用**槽位制**：6 个槽位、间距 1.0 格，每只记自己的法线偏移、每帧被拉回，不做物理分离（同队成员跳过分离循环，否则「分离」与「回槽」两套力每帧互相拉扯，队伍抖成筛子）。间距 1.0 必须大于 2×碰撞半径（0.42），不然这两股力注定打架。撞到主角掉血，并把人沿**队伍法线**挤开 —— 沿径向挤会把人一路顶着走、直推到墙角出不来。
- **旗手**（`bearer`，队列中间举木牌那只）：生命 7。砍死它整队**崩散 4 秒**（站住不动、期间受到的伤害 ×2，配一记金色爆发）。所以「先拆旗手，再吃那 4 秒」是这关唯一的正解，一只只砍是最亏的打法；反过来，缝补小巫会把散掉的队伍重新扶起来，是优先清理对象。
- **木牌是程序化贴图，零新资产**：第 81 块给无名者 / 旗手做过胸前牌和举杆牌，第 83 块这套贴图留给了**寄存处看守** —— 它胸口那块大木牌（0.70×0.46×0.07）就是「收牌子的」。踩过的三个坑都在注释里：① 挂件要**反向缩放**（`model.scale ≈ 1.02` 时也要套一层 `holder.scale.setScalar(1/s)` 才能按世界单位写尺寸）；② 牌子必须是**有厚度的 Box**，零厚度 Plane 一侧身就退化成一条线；③ 材质必须用**不吃光的 `MeshBasicMaterial`** —— 用受光材质会被 `cfg.tint` 整片覆盖颜色、再被 `cfg.glow` 盖一层自发光，最后渲染成一块深棕近黑的小方片，夜里压在深灰地面上**和「根本没画」一模一样**（为这个查了三轮相机投影）。现在 `userData.isTag` 会把木牌从 tint / 材质 clone / 受击闪白里摘出去；`attachTag` 的尺寸也从写死改成读 `cfg.tagBox / tagY / tagZ`（看守的牌子比骷髅的大一圈）。
- **寄存柜**（`js/deposit.js`，第 83 块整块重做、第 84 块调概率）：立在场地**外面**的哨亭（z=-19.2），3.0×2.2×1.0 柜体 + 顶檐 + 两侧立柱 + 4×2 八格柜面。**约一半的怪倒下会掉一块木牌飞进柜子**（第 84 块从「必掉」改成 50% —— 第八关 20 回合五百多只怪，必掉的话柜子会开几十次；概率的真相源是 `TAG_SEAL`，法器镇牌铃每升一级往下压一档）；亮满 8 格的那一瞬间**当场封柜**：牌子再也取不出来，柜面转成暖色并写上「封柜」，地上亮起一圈金环从外往内收，**5 秒后柜门自己开**，走出一只**寄存处看守**。柜体有圆形碰撞，人撞不进去也穿不过去。
- **取牌 = 不冻结世界的四位数字**：站到柜边（3.6 格内）会在屏幕底部冒出「取牌 · n/8」按钮，按下去右下角弹一个 206px 的面板：上面是随机的**四位数**（如 3928），下面是游戏内置键盘。**敲满四位自动判**，对了就把柜里的牌子全拿走；12 秒内没输完、或输错，牌子留在柜里，3 秒后能再试。这是刻意做成**不暂停**的 —— 用户定案「世界不冻结、边打边输」，所以面板只在自己那块矩形里吃点击，左半屏的摇杆照旧能推。
- **柜子为什么放在场地外**：场地半径 18、玩家走到最边上 r≈17.7，离柜子只有 1.5 格，正好在按按钮的范围里；而怪不会从柜子上穿过去。封柜那 5 秒是给玩家的**撤离窗口** —— 要么现在去把柜子清掉（清不掉，封了就锁），要么趁着还有几秒拉开距离准备接 boss。
- **关卡数据**：arena 18，20 回合 5 幕（寄存层 → 柜子开始攒 → 第一次封柜 → 两只一起压 → 毕业考）。第 83 块把队形怪（无名者 / 旗手）整块删掉，换成寄存处看守这一条主线：前期靠「攒牌压力」逼你决定要不要花 12 秒去清柜，后期一关能召两三次看守。剧情 s08 绑在第八关第 2 回合。

**第 88 块（本块）：生命模型转型 —— 血量存量扛后期（上限全面提档）**

用户一句话：「提高生命上限的数值再提高」。追问后定案：范围 **全部途径一起提档**，幅度由我定，方向是「之前是生命低、完全靠生命恢复抗伤害，现在要转型成血量存量在后期抗伤害」。

1. **基础上限 6 → 10**。这是整块的地基：开局就有 10 点存量，不再靠每秒 0.05 的回血续命。血条是按比例渲染的（`ratio * 100%`），不是固定格数，上限变大不会撑坏 HUD。
2. **三条属性途径**：厚皮 `2/4/7 → 3/6/10`、传说「不灭」`3 → 6`、商店「硬壳」`2 → 4`（价格保持 14 骨币不涨 —— 转型期要让玩家愿意买血）。
3. **事件里的「生命上限 +N」整体翻倍**：53 处结算数据 + 61 处文案，按 `{1→2, 1.5→3, 2→4, 3→6, 4→8}` 映射。**代价（`cost.hp`）与扣血（`hp: -N`）一律没动** —— 它们和「补血」是两套语义。
4. 「生命回满」的固定增量 `HEALFULL_UP 2 → 4`；小药 `3 → 4`（上限 10 以后回 3 只顶 30%，一罐药会显得像开玩笑）。
5. **局外那三条保持 +1**（篝火 / 永夜火种 / 夜行商店「强健」）：基础抬到 10 以后，+1 的相对权重自动变小，正好符合「局外因素对局内影响要小」的铁律。
6. 顺手修掉一处旧数据不一致：「把手伸进井水里」的文案一直写着「生命上限 +4」，实际结算只有 2 —— 新加的对账断言把它抓出来了。

**第 87 块：三处平衡性调整（续航类整体降档）**

用户三件事：①「每秒生命恢复选项数值提升变为原来的四分之一左右」②「把回复血量的选项全部统一为提高生命上限的同时补生命」③「近战攻击吸血量的选择提升全部变为原来的三分之一左右」。追加：药水不改消耗品定位，但**取消购买上限、降低价格**。

1. **再生（`hpRegen`）0.2 / 0.36 / 0.65 → 0.05 / 0.09 / 0.16**（约 1/4）。传说卡「不灭」附赠的回血 0.3 → 0.08（不跟着降的话，它会成为唯一值得拿的续航）。属性面板的 `hpRegen` 格式改成「小于 0.1 时显示两位小数」，否则 0.05 和 0.09 都被 `toFixed(1)` 抹成「0.1」，看起来像没改。
2. **近战吸血 10% / 18% / 32% → 3% / 6% / 11%**（约 1/3）。吸血是乘在伤害上的，攻速一高就指数往上翻，原来最大档等于「每一下都回满」。血剑的「活血」（`leechRate`）是另一条属性，这次不动。

## 第 96 块（v=110）：寄存处看守从三招扩到五招

用户：「再丰富寄存处看守的攻击方式，例如抛出牌子砸人，或者其他方向，向我提问」。
先确认了一件事：**「抛牌子砸人」本来就已经是它的一招**（9 格外那块抛物线飞过来的木牌），
所以真正要做的是补它缺的**维度**，而不是再加一块同样的牌子。追问后定案三条：
加 **扇形木牌雨 + 砸开寄存柜** 两个维度 / 投牌改成 **会拐一次的追踪牌** / **全程轮换且出手更密**。

### 1. 为什么是「扇形」和「砸柜」

原来的三招（横扫 / 砸地三连圈 / 投牌）形状**全是圆的**，所以「离中心远一点」永远是对的 ——
玩家从来不需要判断**方向**，只需要判断**远近**。这是这套招式最大的单调来源。
扇形是唯一能补上「角度」这一维的：它只往正面 90° 张开，**往后退完全没用**，必须绕到侧面或背后。

砸柜补的是另一种东西 —— 它自己不打人，产出的是**场面**。柜子本来就是它的地盘，
打不动就回身一锤把柜门砸开，放里头「没人来领的寄存物」出来按手按脚。

### 2. 五招的距离带（同一距离不再是固定一招）

| 招 | 触发距离 | 前摇 | 长相 | 怎么躲 |
|---|---|---|---|---|
| ① 横扫 | ≤ 3.6 格 | 0.55s | 脚下一圈橙光 | 退一步 |
| ② 砸地 | 3.6 ~ 9 格 | 0.55s + 落 1.35s | 你脚下 + 两侧共三个金圈 | 走两步 |
| ③ 木牌雨（新） | 3.6 ~ 8.6 格 | **0.95s** | **正面 90° 扇面** | **绕到侧面或背后** |
| ④ 投牌 | > 9 格 | 0.55s | 一块会拐弯的飞行木牌 | 闪一次 → 再闪一次 |
| ⑤ 砸柜（新） | > 4.2 格 | 1.20s | 柜门崩开、小怪涌出 | 趁着前摇先压上去 |

中距（3.6~8.6）现在是「砸地 / 木牌雨」**各一半**，以前站住不动就能把节奏背下来。
砸柜有**自己的冷却**（出场 6 秒后才允许第一次，用完再等 16 秒），不占常规出手节奏，
所以五招会自然地轮着出。

### 3. 扇形的两个硬约束

**① 画面和判定必须同源。** 扇面用 `CircleGeometry(r, 40, -half, half*2)` 再 `rotateX(-π/2)`
落到 XZ 平面（局部朝 +X），靠 `mesh.rotation.y = angle - π/2` 转到世界方向；
判定用 `Math.atan2(pp.x - st.x, pp.z - st.z)` —— 和 `root.rotation.y` 是**同一套 `atan2(dx, dz)` 约定**。
两边分开写就是「画在这、打在那」，这是这个项目已经踩过一次的老坑。

**② 方向在出手那一帧就锁死。** 扇面和判定是**一起**在 cast 那一帧铺好的（`delay = 前摇`），
所以「看到扇面亮起来还来得及绕」成立；如果等前摇结束才铺，玩家就没有反应余地了。

**③ 几何是共享缓存。** `fanGeo()` 只建一份（半径和半角都是常量），所以销毁时只能
`material.dispose()`，**不能 dispose 几何** —— 跟那些一次性的落点圈不一样。

### 4. 投牌：有转向速率，也有转向预算

改之前是「出手那一刻算好一个点，直线飞过去」。现在是一块**有速度、有朝向**的东西：

- `tagHome` **3.2 rad/s** —— 转向速率上限（不是瞬移对准）；
- `tagTurn` **1.15 rad（约 66°）** —— **总转向预算**，拐完就直飞（`turnLeft` 归零后朝向彻底冻住）；
- `tagFuse` **1.25 格** —— 近炸引信；`tagR` 从 2.2 **收小到 1.9**（因为更难躲了）。
- `tagLife` **2.8 秒** —— 最长飞行时间，防止绕圈到天荒地老。

于是躲法从「横移一步」变成：**闪一次 → 它跟着拐 → 再闪一次才甩掉**。
无限追踪是不行的 —— 那会变成只能靠无敌帧硬吃，是猜谜不是走位。

### 5. 顺带修掉一个真 bug：看守的出手从来没吃过 `haste`

第 91 块给全场加了「出手频率」这一维，`main.js` 召唤看守时也传了 `hasteScale`，
注释还专门写着「看守的出手也要跟着回合变密」。但 `handleWarden` 里写的是：

```js
e.wdGap = Math.max(0.5, cfg.gap * (e.raged ? cfg.rageGap : 1));   // 没读 e.haste
```

也就是说第 15 回合的看守和第 1 回合同样从容。这一轮改成 `cdOf(e, cfg.gap * 狂暴倍率, 1.1)`
（第 91 块立的规矩：所有出手机制只走 `cdOf` 一个出口），floor 1.1 秒保证再密也留得出一条走位缝隙。
配合 `gap 2.4 → 2.0`，同一回合的出手密度大约是原来的 1.2 倍、再叠上攻速成长。
